## 2026-09-09 (2) — Slice 1.2: Product

### Goal

ROADMAP 1.2: `Product` + `Sku`/`Money` value object'leri + CRUD + unique SKU (409).

### Done

- **Domain:** `ProductId`, `Sku` (büyük harfe normalize, `ToUpperInvariant`), `Currency` (1'den
  başlayan enum), `Money` (negatif ve >2 ondalık reddedilir), `Product` (SKU create'den sonra
  değişmez). `RequiredText` ikinci tüketici doğunca çıkarıldı; Category de ona bağlandı.
- **Application:** 4 ürün handler'ı + kategori update/delete handler'ları. `ICatalogDbContext`
  yalnız `DbSet<Product>` kazandı.
- **Infrastructure:** 3 yeni converter, `ProductConfiguration` (`ComplexProperty` ile Money iki
  kolona, unique SKU index'i, FK `Restrict`), `AddProducts` migration'ı.
- **Api:** ürün CRUD + kategori PUT/DELETE (8 endpoint), `23503` → 409 eşlemesi,
  `TypedIdSchemaTransformer` tip kümesine genelleşti.
- **Testler: 35 → 85.** Elle doğrulamanın 7 senaryosu da geçti; şema ve Jaeger trace'leri teyit edildi.

### Learned

- **`ComplexProperty` value object için doğru araç.** Owned type ayrı kimlik/gölge anahtar getirir;
  `Money`'nin kimliği yok, sadece iki kolon olarak satırda durması gerekiyordu.
- **Test fixture'ının kendi serializer kopyası tehlikeli.** Ürün testleri ilk koşuda 4 hata verdi:
  API `ProductId` yazmayı öğrenmişti, test listesi okumayı öğrenmemişti. Çözüm listeye ekleme
  yapmak değil, ayarları uygulamanın container'ından okumak oldu — ayrışma artık imkânsız.
- **`ToUpper()` vs `ToUpperInvariant()`** tr-TR'de aynı SKU'yu iki farklı şeye çeviriyor. Testte
  kültürü bilerek tr-TR'ye sabitleyip invariant yolun kullanıldığını kanıtladık.
- EF Core, FK ihlalinde kendi `Error` seviyesinde log'unu düşürüyor; biz 409'a çevirsek de bu kayıt
  kalıyor. Davranış doğru, gürültü kabul edildi.

### Decisions

- SKU değişmez (ERP/pazaryeri referansı) → `UpdateProductRequest`'te alan yok.
- Slug değişmez (public URL) → `UpdateCategoryRequest`'te alan yok.
- `DeleteCategoryHandler` ürün kontrolü yapmıyor; kısıt veritabanında, yarış penceresi yok.
- Typed id JSON converter'ları açık kalıyor; factory eşiği 4. id.

### Problems

Yok. (Gün başında VS 2022'nin .NET 10 projelerini açamadığı anlaşıldı → VS 2026 kuruldu, 2022 duruyor.)
