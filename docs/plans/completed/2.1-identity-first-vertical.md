# Slice 2.1 — Identity, first vertical

**Status:** Completed 2026-10-02. Phase map: `faz-2-identity-gateway-frontend.md`.
**ADRs:** 0011 (auth model), 0019 (own user store), 0018 (error codes), 0003 (own database).

## Goal

A second service, end to end: register, log in, receive an RS256-signed access token,
and verify it against the published JWKS. Same discipline as Catalog: four layers,
migration, Testcontainers tests, Dockerfile, CI.

## Scope

| Endpoint | Behaviour |
| --- | --- |
| `POST /api/v1/auth/register` | `{ email, password, displayName }` → 201 with the user. No token: registering is not logging in. Duplicate email → 409 `identity.user.email_conflict`. |
| `POST /api/v1/auth/login` | `{ email, password }` → 200 `{ accessToken, tokenType: "Bearer", expiresIn: 900 }`. Unknown email and wrong password give the **same** 401 `identity.auth.invalid_credentials`. |
| `GET /api/v1/users/me` | Requires a bearer token; returns the caller. Proves the token round-trips. |
| `GET /.well-known/jwks.json` | The public key(s), with a `kid` derived from the key (RFC 7638 thumbprint). |

**Domain:** `User` (`UserId`, `Email`, display name, password hash, timestamps), `Email`
normalised to lower case with invariant rules (the `İ`/`ı` lesson from Catalog applies:
`ToLowerInvariant`, never `ToLower`).

**Password policy:** 8–128 characters, nothing else (NIST 800-63B: length over composition
rules). The upper bound stops a megabyte "password" from being hashed 100k times.

**Token:** 15 minutes; claims `sub`, `email`, `name`, `jti`, `iat`; issuer
`akiron-identity`, audience `akiron`. Signed with RS256 by a key from
`Identity:SigningKeyPath`. Development generates the key on first boot into a git-ignored
file; any other environment refuses to start without one.

## Learning milestones

1. **Mint vs verify.** Only Identity holds the private key; anyone can fetch the public
   one. Tests prove a token signed by a *different* key, a token with an edited payload,
   and an `alg: none` token are all rejected.
2. **User enumeration by timing.** Naive login returns early for an unknown email, so it
   answers measurably faster than for a wrong password — the response body is identical,
   the clock is not. Measure it, then fix it by verifying against a dummy hash when the
   user does not exist. Recorded in the devlog with numbers.
3. **The unique index under a race**, as in Catalog: two concurrent registrations of the
   same email → exactly one 201 and one 409, never a 500.

## Deliberately duplicated

Serilog/OTel/ProblemDetails wiring, `DomainException` and friends are copied from
Catalog, not shared. That duplication is the evidence the rule of two asks for; slice
2.2 extracts them into `Akiron.ServiceDefaults` with both services as consumers.
Architecture tests for Identity also wait for 2.2, so the rules are written once.

## Out of scope

Refresh tokens (2.3), dealers and price-group claims (2.4), lockout and password reset
(gateway rate limiting in 2.5 is the brute-force defence until then — ADR-0019).

## Done when

Tests green in CI · `docker run` of the image answers `/health/ready` and the JWKS ·
a token from `/login` verifies on jwt.io with the JWKS key · devlog entry · ROADMAP note.
